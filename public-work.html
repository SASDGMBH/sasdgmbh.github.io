Documentation focus

Engineering documentation

SASD projects emphasize requirements, architecture, implementation notes and operational documentation because maintainability is part of the product.

Repository status matters.

Each public repository should clearly state whether it is a demonstration, prototype, template, library or production-ready component.

Recommended repository labels

For customer-facing clarity, public projects should use simple and honest status language.

Demo

Shows an idea, pattern or technical capability. Not intended as a full product.

Prototype

Used to validate architecture, UI or feasibility before committing to a full implementation.

MVP

A small but useful first version with clear limitations and next steps.
